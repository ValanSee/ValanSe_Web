### PC 레이아웃 (`lg` ≥ 1024px)

- 모바일 헤더·카테고리 탭바 대신 좌측 220px **사이드바**(스크롤 시 상단 고정)

## 🧩 섹션별 상세 명세

### 1. HOT 인기 급상승 드롭다운 (HotTrendingBar)

**표시 데이터**: 통합 트렌딩 API의 상위 1~5위 (`votes[]`). 각 항목은 순위(`displayOrder`)·`displayType`(PINNED 관리자 고정 / RANKED 반응성 순위)·제목을 가진다.

- **접힘 상태**: `[HOT]` 칩 + 1위(`votes[0]`) 제목 + 펼침 화살표(▼)
- **펼침 상태**: 1~5위 순위 리스트

**사용 API**: `fetchTrendingVotes(7)` → `GET /votes/trending?days=7` (hotissue/trending 통합 API, 기간 7일)

**사용자 액션**: 바 클릭 → 펼침/접힘 토글 · 랭킹 항목 클릭 → `/poll/[voteId]`

**상태별 처리**: 노출 가능한 `votes`가 비면 바 자체를 렌더하지 않음

### 3. BalanceList

**표시 데이터**: 페이지네이션된 게임 목록

**사용 API**: `fetchVotes`

**렌더링 (SEO)**

- 첫 페이지 10개를 서버에서 비로그인으로 조회해 SSR (`fetchVotesForServer`, 60초 캐시) → HTML 에 `/poll/{id}` 링크 포함
- 카테고리·정렬 변경 시 서버가 새 첫 페이지를 내려주므로 클라이언트 재조회 없음. 이후 스크롤은 서버 커서로 5개씩 이어서 로드
- 알 수 없는 `category`·`sort` 값이거나 서버 조회 실패 시 기존처럼 클라이언트에서 조회
- 목록 끝(다음 페이지가 있을 때)에 `다음 밸런스게임 보기` 링크(`rel="next"`, `?cursor=`)를 둠 → 무한 스크롤을 못 하는 크롤러가 이어지는 상세 링크를 따라감. 사용자는 보통 무한 스크롤이 먼저 동작
- `?cursor=` 페이지: 서버가 그 지점부터 10개를 SSR, `noindex, follow` · canonical 없음(커서는 새 글마다 바뀌는 주소). 상단에 `← 처음부터 보기`, 이후 무한 스크롤은 그대로
- 카드 → 상세 링크는 쿼리 없이 `/poll/{id}` (예전 `?source=balance` 는 쓰이지 않아 제거, 중복 URL 방지)

**사용자 액션**

- 카드 클릭 → `/poll/[id]`
- 스크롤 → 다음 페이지 로드
- 관리자: PinButton

**상태별 처리**

- **로딩**: 스켈레톤 카드
- **빈 상태**: "해당 카테고리에 게임이 없어요"
- **에러**: 재시도 버튼

## ⚠️ 예외 상황

| 상황 | 처리 |
|---|---|
| 내가 신고한 투표 | 신고자 화면에서만 목록에서 제외. 제외 후 비면 "해당 카테고리의 밸런스게임이 아직 없어요" 노출 (로컬 저장 기준, 기기별) |
| 내가 신고한 투표가 HOT 랭킹에 포함 | HotTrendingBar 랭킹에서도 제외. 전부 제외되면 바를 렌더하지 않음 |
