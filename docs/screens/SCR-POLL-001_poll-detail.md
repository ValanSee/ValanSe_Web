## 🎯 화면 목적

특정 밸런스 게임의 선택지·통계·댓글을 보고, 투표 및 댓글 작성에 참여한다. 고정·삭제 같은 관리 기능은 CMS로 이관되어 이 화면에는 없다.

## 🚪 진입 경로

- 홈 핫이슈 카드
- 밸런스 목록(`/balanse`)의 아이템
- 내 이력(`/my/created`, `/my/voted`)
- 외부 공유 링크 (헤더 공유 버튼으로 공유된 `/poll/{id}`)

## 🖥️ 렌더링 (SEO)

- 서버에서 `GET /votes/{id}` 를 **비로그인**으로 조회해 PollCard 를 SSR (60초 캐시, 3초 타임아웃)
- 같은 데이터로 페이지별 `title` · `description` · canonical(`/poll/{id}`) · OG 생성
  - title: `{제목} - {카테고리} 밸런스게임 | ValanSe`
  - description: 본문 · `A vs B` · 안내 문구 (150자 이내)
  - JSON-LD: DiscussionForumPosting(참여 수 `interactionStatistic` VoteAction · 댓글 수 `commentCount` 포함) · BreadcrumbList
  - OG · 트위터 이미지: 게임별 자동 생성 (`opengraph-image.tsx`, 1200×630 — 카테고리 · 제목 · A vs B). 상세 조회 · 폰트 로드 실패 시 공통 `og-image.png`
- 클라이언트에서 로그인 토큰으로 다시 조회해 `hasVoted` · 댓글 등을 갱신 (로딩 화면 없이 교체)
- 로그인 사용자(토큰 있음)는 재조회 전까지 **선택지·참여자 수 자리에 스켈레톤** 노출 → 미투표 화면이 먼저 보이지 않음
  - 비로그인·크롤러는 SSR 선택지를 바로 노출
  - 재조회 전 선택지 클릭·로그인 후 대기 투표 자동 제출은 막음
- 서버 조회가 실패·타임아웃이면 기존처럼 클라이언트에서만 조회
- 베스트 댓글(`GET /votes/{id}/comments/best`) · 댓글 첫 페이지(`GET /votes/{id}/comments`)도 서버에서 상세와 함께 조회해 SSR → 댓글이 늦게 붙으며 아래 영역이 밀리던 CLS 제거, 댓글 텍스트 색인. 클라이언트는 이 값으로 시작해 로그인 기준으로 다시 조회. 실패한 항목만 클라이언트 조회로 대체
- 라우트는 `app/(public)/poll/[id]` — 로딩 화면(`loading.tsx`)·AuthGuard 의 Suspense 가 없는 그룹이라, 없는 게임이면 응답이 스트리밍되기 전에 `notFound()` 가 실행돼 실제 HTTP 404 를 반환 (예전 `(auth)` 그룹에서는 200 + noindex 소프트 404). 상세는 로그인 강제 대상이 아니라 AuthGuard 불필요
- 같은 카테고리 인기 게임 목록도 서버에서 조회해 내부 링크로 SSR (PC 사이드바 · 모바일 하단 목록, Suspense 로 따로 스트리밍) → 크롤러가 다른 상세 페이지로 이동할 수 있음

## 📐 레이아웃 구성

1. **헤더** (뒤로 / 공유 버튼 / 게시글 메뉴 — 신고). PC 는 브레드크럼 오른쪽에 같은 버튼
2. **PollCard** (제목, 선택지 A/B, 투표 버튼)
3. **VoteChart** (참여 통계)
4. **베스트 댓글 미리보기** (PreviewCommentCard)
5. **전체 댓글 (CommentDetail)** — 펼치기/시트, 댓글별 메뉴(삭제/신고)
6. **같은 카테고리 인기 밸런스 (RelatedPolls, 모바일 전용 — PC 는 사이드바)**
7. **ReportSheet** (신고 사유 선택 바텀시트)
8. **하단 네비게이션 바**

### PC 레이아웃 (`lg` ≥ 1024px)

- 투표 제목이 화면의 h1 (모바일 헤더의 '밸런스 게임' 은 제목 태그 아님)
- 모바일 헤더(뒤로가기·제목) 대신 **브레드크럼** `홈 / {카테고리} 밸런스게임` + 우측 더보기(신고) 메뉴
- **2단 구성**: 좌측 투표 카드 · 결과 차트 · 베스트 댓글 · 댓글 목록 · 댓글 입력(하단 고정 대신 카드로 배치) / 우측 340px 사이드바(스크롤 시 상단 고정)
- **사이드바**: `{카테고리} 인기 밸런스`(같은 카테고리 인기순) · `새로 올라온 밸런스`(전체 최신순) 각 최대 5개, 현재 글·내가 신고한 글 제외. 서버에서 조회해 SSR HTML 에 링크 포함. 목록이 비면 해당 섹션 미노출, 둘 다 비면 사이드바 칼럼 자체를 숨김. 사이드바는 Suspense 로 따로 스트리밍해 본문 응답을 지연시키지 않음. 서버 상세 조회가 실패해 클라이언트에서 다시 조회하는 경우엔 사이드바 미노출

## 🧩 섹션별 상세 명세

### 0. 공유 버튼 (헤더)

**사용자 액션**

- 클릭 → 휴대폰 기본 공유 시트(Web Share API) 열림. 제목 `{투표 제목}`, 문구 `{투표 제목} — A vs B, 너라면 뭐 골라?`, URL `https://valanse.kr/poll/{id}` (쿼리 없는 canonical)
- 공유 시트를 지원하지 않는 환경(PC 브라우저 일부 · Android 앱 WebView) → 링크 복사 + 토스트 `링크를 복사했어요`, 실패 시 `링크를 복사하지 못했어요`
- 공유 시트를 닫으면 아무 동작 없음
- 공유 미리보기 이미지는 게임별 OG 이미지(`opengraph-image.tsx`)

### 2. VoteChart

**사용 API**: `fetchBestVote`

### 3. 베스트 댓글 / 전체 댓글

**사용자 액션**

- 댓글 입력 / 등록
- 댓글 삭제 (본인 댓글만)
- 댓글·대댓글 `⋮` → "신고" → ReportSheet (본인 글·삭제된 글은 메뉴에서 제외)
- 댓글·대댓글 하트 → 좋아요 토글 (`POST /votes/{id}/comments/{commentId}/like`)
  - 결과를 토스트로 안내: "좋아요를 눌렀어요" / "좋아요를 취소했어요" / 실패 시 "좋아요 처리에 실패했어요"
  - 이번 방문에서 누른 댓글은 하트가 채워진 보라색으로 표시 (서버가 눌림 여부를 내려주지 않아 새로고침하면 초기화)
  - 미로그인이면 누른 댓글을 저장한 뒤 바로 `/entry` 로 이동 → 로그인 후 이 화면으로 돌아오면 자동으로 좋아요 반영 (대댓글이면 펼쳐서 표시). 이미 좋아요한 댓글이라 토글로 취소되면 한 번 더 눌러 좋아요 상태로 맞춤

### 4. 같은 카테고리 인기 밸런스 (RelatedPolls, 모바일)

**노출**: `lg` 미만에서만 댓글 목록 아래 카드로 노출. PC 는 우측 사이드바의 `{카테고리} 인기 밸런스` 가 같은 역할

**표시 데이터**: 같은 카테고리 인기순 최대 5개 (현재 게임 제외) — 제목 · `A vs B` · 참여자 수. PC 사이드바와 같은 요청이라 fetch 캐시로 한 번만 호출

**사용자 액션**

- 항목 클릭 → 해당 게임 상세(`/poll/{id}`)
- 헤더 `더보기 >` → 카테고리 인기순 목록(`/balanse?category={카테고리}&sort=popular`)

**상태별 처리**

- 조회 실패 · 결과 없음 · 상세 서버 조회 실패 시 섹션 미노출
- 내가 신고한 투표는 목록에서 제외 (로컬 저장 기준)

### 5. ReportSheet (신고 바텀시트)

**진입**: 게시글 메뉴 / 댓글·대댓글 메뉴의 "신고"

**표시 데이터**: 신고 사유 9종 (스팸 · 영리목적/홍보성 · 도배/정치 · 성적 콘텐츠 · 혐오 또는 괴롭힘 · 폭력 또는 위협 · 불법 또는 유해 콘텐츠 · 개인정보 노출 · 기타) — 서버 `ReportReason` enum과 동일

**사용자 액션**

- 사유 1개 선택 (필수) + 상세 내용 입력 (선택, 1,000자 이하)
- "신고하기" → `POST /report/{targetId}` → 접수 완료 팝업

**상태별 처리**: 사유 미선택 시 제출 버튼 비활성. 미로그인 상태에서 "신고" 클릭 시 시트 대신 바로 `/entry` 로 이동

## 🔄 사용자 시나리오

**시나리오 1: 미참여 사용자 투표**

1. `/poll/[id]` 진입
2. 선택지 A 클릭
3. 결과 차트 노출 + 댓글 영역 활성화

**시나리오 2: 부적절한 댓글 신고**

1. 댓글 우측 `⋮` → "신고"
2. 바텀시트에서 사유 선택 (필요 시 상세 내용 입력)
3. "신고하기" → "신고가 접수되었습니다." 팝업 (검토 최대 24시간 안내)
4. 팝업 확인 → 해당 댓글이 "신고한 콘텐츠입니다" 블라인드로 즉시 전환

## ⚠️ 예외 상황

| 상황 | 처리 |
|---|---|
| 존재하지 않는 id (서버 404 · 숫자가 아닌 id · 삭제된 게임) | 공통 404 페이지 (`app/not-found.tsx`, `noindex`), **HTTP 404** |
| 서버 조회 실패 · 타임아웃 | 클라이언트 조회로 대체. 그마저 실패하면 "투표 정보를 불러오지 못했습니다" |
| 이미 투표한 게임 | 선택지 비활성화, 결과 즉시 노출 |
| 미로그인 + 투표 시도 | 바로 `/entry` 로 이동 → 로그인 후 복귀 시 자동 투표 |
| 미로그인 + 댓글 좋아요 시도 | 바로 `/entry` 로 이동 → 로그인 후 복귀 시 자동 좋아요 + 토스트 |
| 미로그인 + 신고 시도 | 바로 `/entry` 로 이동 (복귀 경로 유지) |
| 이미 신고한 대상 | 서버 400 `이미 신고한 대상입니다.` 를 그대로 팝업 노출 |
| 본인 게시글·댓글 | 신고 메뉴 미노출 (서버도 400으로 거부) |
| 삭제된 댓글 | 신고 메뉴 미노출 |
| 내가 신고한 댓글·대댓글 | 본문·작성자·좋아요·`⋮` 를 모두 감추고 "신고한 콘텐츠입니다" 만 노출. 원문 보기 토글 없음 (로컬 저장 기준, 기기별) |
| 내가 신고한 투표 | 목록(홈·밸런스)에서 제외. 상세 페이지 본문은 그대로 노출 |

## 🔌 사용 API

| Method | Endpoint | 용도 |
|---|---|---|
| GET | `/votes/{id}` | 상세 조회 (서버: 비로그인 SSR·metadata / 클라이언트: 로그인 기준 재조회) |
| GET | `/votes/{id}/comments` | 댓글 목록 |
| GET | `fetchBestComment` | 베스트 댓글 |
| GET | `fetchBestVote` | 통계 |
| POST | `/votes/{id}/comments` | 댓글 작성 |
| POST | `/votes/{id}/comments/{commentId}/like` | 댓글·대댓글 좋아요 토글 (비로그인은 서버 403) |
| DELETE | `/comments/{id}` | 댓글 삭제 (본인) |
| POST | `/report/{targetId}` | 투표·댓글 신고 (`reportType`, `reason`, `content`) |
| GET | `/votes?category={카테고리}&sort=popular&size=6` | PC 사이드바 · 모바일 하단 같은 카테고리 인기 (서버, 비로그인, 같은 요청 공유) |
| GET | `/votes?category=ALL&sort=latest&size=6` | PC 사이드바 최신 (서버, 비로그인) |
