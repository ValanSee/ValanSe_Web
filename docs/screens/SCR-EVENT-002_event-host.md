# 화면 명세서: 행사 투표 사회자 (Event Host)

## 🎯 화면 목적

사회자가 폰이나 노트북에서 방을 조작한다: 입장 인원 확인 → 첫 질문 시작 → (응답 수 보며) 결과 공개 → 다음 질문 → 종료. 집계는 공개 전에도 사회자에게만 보인다.

## 🚪 진입 경로

- 방 생성 응답의 `hostUrl` (`?key=` 포함). 키는 첫 진입 시 sessionStorage 에 저장하고 주소창에서 지운다
- 키 없이 열면 키 입력 폼

## 📐 레이아웃 구성

1. **방 정보** (코드·이름·입장 인원·상태)
2. **대기** (`lobby`): 입장한 닉네임 칩 목록 + `첫 질문 시작`
3. **진행** (`live`): 질문, 응답 n/m, 집계 막대, `이전` · `결과 공개/다시 가리기` · `다음 질문`(마지막이면 `마지막 질문 끝내기`)
4. **종료** (`ended`): `처음부터 다시 시작`
5. `게임 종료` (종료 전 항상)

## 🧩 동작

| 버튼 | action | 결과 |
|---|---|---|
| 첫 질문 시작 / 처음부터 | `start` | `live`, index 0, 비공개 |
| 다음 질문 | `next` | index+1, 비공개. 마지막이면 `ended` |
| 이전 | `prev` | index-1, 비공개 |
| 결과 공개 / 다시 가리기 | `reveal` / `hide` | 참가자·프로젝터에 집계 노출 토글 |
| 게임 종료 | `end` | `ended` |

- 모든 요청은 헤더 `x-host-key`. 키가 틀리면 403 → 문구 표시
- 상태는 폴링(`GET /api/event/rooms/{code}` + 헤더, 진행 중 2초 · 그 외 4초)으로도 갱신되어 두 기기에서 동시에 열어도 된다

## ✅ 수용 기준

- Given 올바른 키 When `첫 질문 시작` Then 참가자·프로젝터가 2초 내 첫 질문으로 전환
- Given 진행 중 When `결과 공개` Then 참가자는 선택 불가 + 비율 표시, 프로젝터는 큰 막대
- Given 잘못된 키 Then 403 문구, 조작 불가

## 🔌 사용 API

| Method | Endpoint | 용도 |
|---|---|---|
| GET | `/api/event/rooms/{code}` (x-host-key) | 사회자 상태 (집계·참가자 목록) |
| POST | `/api/event/rooms/{code}/host` | `{ action }` |
